# Промпт для продолжения проекта CoolChess

Ты работаешь над новым лендингом шахматной школы CoolChess в `C:\Users\elpil\Dev\elmar_site`. Отвечай пользователю по-русски. Исходный дизайн — локальный файл `Chess 2.fig`; действующий прежний сайт — `https://coolchess.ru/`. Цель проекта: сверстать новый сайт по макету, перенести запись на пробный урок и оплату со старого сайта, вести изменения в Git и показывать результат заказчику на `https://secretinc.ru/`.

## Текущее состояние

- Сайт статический: `index.html`, `styles.css`, `refinements.css`, `main.js`, изображения в `assets/`, юридические PDF в `docs/`. Локальный запуск: `python -m http.server 4173`, адрес `http://localhost:4173/`.
- Git-репозиторий создан. Последний коммит с правками сайта на 3 октября 2026 года — `39b3658` (`Align landing page sections with Figma design`).
- На сервере установлен Nginx. Сайт доступен по `https://secretinc.ru/`; HTTP перенаправляется на HTTPS. Сертификат самоподписанный, поэтому браузер показывает предупреждение. Конфигурация Nginx хранится в `deploy/secretinc.ru.nginx`.
- Рабочий выпуск сайта на сервере: `/var/www/secretinc.ru/releases/20261003-2`, путь `/var/www/secretinc.ru/current` ссылается на него. Предыдущий выпуск `20261003-1` сохранён для отката. Файлы `index.html`, оба CSS, `main.js` и выборочные изображения были сравнены по SHA-256 с версиями на сервере; они совпали.
- `ssh_creds.txt` содержит доступ к серверу. Файл исключён из Git. Не выводи его содержимое в ответы, логи и коммиты. `Chess 2.fig` (около 950 МБ), `tmp/` и `tools/` тоже исключены из Git.

## Что реализовано

1. Из прежнего сайта перенесена запись на пробный урок через действующую форму AlfaCRM. На локальном и демонстрационном доменах кнопка переводит прямо на форму. Для `coolchess.ru` предусмотрено встроенное окно; внешняя форма может ограничивать встраивание на иных доменах.
2. Тарифы для занятий 25, 45 и 60 минут и пакетов находятся в `main.js`. Форма оплаты отправляет `service_name`, `sum`, `clientid`, `client_email`, `client_phone` методом POST на действующий PayKeeper `https://coolchess1.server.paykeeper.ru/create/`. Перед отправкой запрашиваются ФИО, email, телефон и три согласия. Реальная тестовая транзакция не проводилась.
3. После замечания пользователя о плохом соответствии макету восстановлен отдельный второй блок «Персональные занятия с профессиональным тренером». Основной порядок секций теперь: первый экран → профессиональные занятия и преимущества → программы по возрасту → подбор обучения → стоимость → этапы обучения → результаты → тренеры → пробный урок → лицензия → дети и турнир → список образовательных программ → подвал.
4. Исправлены адаптивные стили, из-за которых на узком экране текст и изображения налезали друг на друга. Добавлены четыре тренера из макета, история учеников, поддержка оплаты материнским капиталом, список образовательных программ и недостающие детали пробного урока. Основные новые правила находятся в `refinements.css`.

## Что проверено

- Визуальный просмотр локальной страницы на ширинах 1440 и 390 пикселей; на 320 пикселях проверена геометрия документа. У соседних секций нет пересечений; изображения загружаются; горизонтальной прокрутки нет.
- Раскрытие пункта в списке образовательных программ и открытие окна оплаты проверены в браузере. Отправка платежа и заявки не выполнялась.
- На публичном домене получены успешные ответы для новой страницы и `refinements.css`; локальные и опубликованные файлы совпали по содержимому.

## Открытые вопросы и следующий шаг

- Продолжить точную визуальную сверку с `Chess 2.fig` по всем секциям. Макет разбирался из локального `.fig` по структуре слоёв и изображениям, но пиксельное соответствие всех экранов пока не подтверждено. При изменениях сверяй также мобильные состояния и не ограничивайся первым экраном.
- В макете для пяти образовательных программ видны действия «Посмотреть» и «Скачать PDF». Сейчас на сайте эти строки раскрываются через `<details>`; исходные PDF программ не найдены и не подключены. Не добавляй фиктивные ссылки: сначала найди реальные документы или запроси их у пользователя.
- До запуска на основном домене проверить полный путь оплаты тестовым платежом на стороне PayKeeper и поведение формы AlfaCRM в предполагаемом домене.
- После следующих правок: проверить локально, создать новый Git-коммит, затем публиковать новый каталог выпуска на сервере и атомарно переключать ссылку `current`. Не перезаписывай предыдущий выпуск и не включай доступы в архив сайта.
